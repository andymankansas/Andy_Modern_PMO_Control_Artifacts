# Security Policy

## Supported Versions

No production-supported version is available yet. Supported versions will be listed when the first stable release is published.

## Reporting a Vulnerability

Do not open a public issue containing credentials, private project data, workbook content, email, Teams messages, meeting artifacts, or personal information.

Use GitHub's private vulnerability reporting feature when enabled. If it is unavailable, contact the repository owner privately through an established organizational channel.

## Data Handling

Contributors must not commit:

- Project RAID or Workback workbooks
- Meeting Monitor artifacts
- Email or Teams exports
- SharePoint or OneDrive tenant links containing private identifiers
- Personal names, mailbox addresses, or machine-specific paths in distributable configuration
- Tokens, passwords, cookies, certificates, or API keys
- Generated proposals, approval manifests, audit logs, or backups

Use synthetic fixtures for tests.
